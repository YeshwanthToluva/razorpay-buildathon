Can an agent recover at-risk revenue better than a rule set?

A frozen experimental record: six runs over the same 50 synthetic failed payments, every decision passed through a deterministic policy engine and written to an append-only ledger.

Evidence and limits

Every arm is n = 1 on one dataset, one seed, one model and one API path. Run-to-run variance has not been estimated — observed spread across repeats of the same configuration is several percentage points, which is larger than most differences shown here. The model budget for this phase is closed, so the replication needed to resolve that was not run. Read the arms as observations, not as a ranking.

Why did the agent lose?

vs deterministic baseline

Every payment is classified by comparing the agent's decisions against the baseline's on the same case. "Correct action" is not a judgement call — it is the highest-probability action for that failure category under the simulator's own published physics.

Payment replay

Reconstructed from the audit ledger. Claims the agent restated about the case are checked against the state it was actually shown, so a contradicted premise is visible next to the decision it produced.

Safety and authorization

the invariant

The agent proposes; it never executes. An AuthorizedAction can only be minted inside the policy module, and the payment provider will not act without one — so a route from proposal to money that skips policy raises an exception rather than moving funds.

0
unsafe actions executed

Across all six runs in this console — and every run recorded in the project — no action reached the payment provider without a policy ALLOW. Unsafe actions proposed are an experimental observation and are counted separately; the deterministic boundary blocked of them here, and let none through.
